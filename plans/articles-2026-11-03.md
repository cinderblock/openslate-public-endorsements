# Articles on the November 3, 2026 California ballot

## Goal

Attach published articles (news, analysis, explainers, guides, labelled opinion) to the
ballot items they cover, as researcher-signed secondhand slates (OpenSlate SPEC §3.15,
§3.9): one `orgs/<slug>/2026-11-03/positions.json` per publisher, `positions: []`,
`articles: [...]`. The web app collates them with each ballot item by subject identity.

Priority: all 14 statewide propositions (1–5, 37–45), about 3–6 articles each across
publishers. Then, if time allows, San Francisco local measures with SF publishers.

## Environment / context

- Worktree: `C:\Users\camer\.t3\worktrees\openslate-public-endorsements\feat-articles`,
  branch `feat/articles`. Commit locally only; no push, no signing.
- Subjects: statewide props use the CA Secretary of State listing's subjects exactly
  (`orgs/ca-secretary-of-state/2026-11-03/positions.json`), e.g.
  `California — Proposition 1 (Authorizes Bonds for Housing Affordability Programs)`,
  kind `measure`, jurisdiction `us/ca`. SF measures use
  `orgs/sf-department-of-elections/2026-11-03/positions.json`.
- Fetching: `curl` (mingw, schannel) fails on these sites; Bun's `fetch` works. Helper
  scripts kept outside the repo, in `%TEMP%\artscripts\` (`meta.ts`: headline, dates,
  canonical URL and prop mentions per URL; `links.ts`: link harvest from index pages).
- The WebSearch tool refuses `latimes.com` and `politico.com`, but Bun `fetch` reads
  latimes.com directly.

## Decisions already made (don't re-ask)

- One slate per publisher; newsroom coverage gets its own slug (`<editorial-slug>-news`)
  when the paper's editorial board is already an org here. Existing orgs' files untouched.
- No `summary`, no article text anywhere (evidence holds metadata plus a one-line note of
  my own).
- `meta.yaml` `kind: news_organization`, no logo for now.
- Editorial-board endorsements are not re-attached as articles (they're already positions
  on the editorial-board org).

## Findings / gotchas

- `scripts/verify-positions.ts` builds its placeholder payload from `positions`,
  `endorsed_by`, `attribution` and `context` only, so it never sees `articles`: an
  articles-only file passes without its articles being checked. Validate articles with
  `slatePayloadSchema` directly.
- KQED's `/voterguide/california/proposition-N` pages have no publish date (only "Updated
  …"); its dated per-prop explainers live under `/news/<id>/…` (linked from
  `kqed.org/propfest`).
- CalMatters guide pages: `article:published_time` 2026-10-01, `<time>` shows later
  update dates; the published date is used.
- Unreachable to scripts from this machine: sacbee.com (connection closed), apnews.com,
  ppic.org, politico.com (Cloudflare 403 to Bun and to WebFetch). The WebSearch tool also
  refuses sacbee.com, apnews.com, latimes.com, mercurynews.com and politico.com.
- sacbee.com and apnews.com load fine in the T3 preview browser (incognito profile; no bot
  check, nothing accepted). Working method:
  - Open a tab with `preview_open` (reuseExistingTab false, open false, profileId
    incognito).
  - Inside it, run the site's own search or sitemap, and fetch article HTML same-origin,
    parsing it with DOMParser.
  - Evaluate calls time out at 15 s, so long loops run in the background on `window.__x`
    and are polled.
  - The default browser profile sends the user's hashed email to ad pixels, so use
    incognito.
- Reprints: sacbee.com carries many (CalMatters, L.A. Times/TNS, S.F. Chronicle, BANG,
  Capital & Main via Reuters), and apnews.com carries CalMatters stories. AP's own 2026
  proposition coverage is only about Prop 40.
- Syndication: Mercury News / U-T rerun each other's stories and Tribune News Service
  (L.A. Times, Sac Bee) and AP copies. Check `<link rel=canonical>` and the byline;
  attach only under the original publisher, at its URL.
- latimes.com `article:published_time` has no offset; use JSON-LD `datePublished` (Z).
  KQED has no `article:published_time`; JSON-LD `datePublished` has a Pacific offset.
- Biome flags every `orgs/**/positions.json` (CRLF working tree, and it would collapse
  short arrays). Existing files all use `JSON.stringify(…, null, 2)` layout; the new files
  match that, not Biome.
- Tooling (outside the repo, in `%TEMP%\artscripts\`): `meta.ts` (page metadata),
  `links.ts` (link harvest), `build.ts` (final.tsv + meta.jsonl -> positions.json,
  evidence/articles.md, meta.yaml), `validate-articles.ts` (schema + exact-subject check).
